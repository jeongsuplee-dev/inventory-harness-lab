# Harness SSOT — 재고관리 PoC

이 문서는 하네스(작업 체계)의 **단일 진실 원천(Single Source of Truth) 지도**다.
정보의 종류마다 원본이 정해져 있으며, 같은 내용을 여러 곳에 복제하지 않는다.

## 2. 원칙

1. **도메인 규칙은 01이 정한다.** 구현이 01과 다르면 구현을 고치거나, 01을 바꾸는 이슈를 따로 연다.
2. **구조·기술 결정은 06이 정한다.** 06에 없는 결정은 이슈에 기록하고, 확정되면 06에 반영한다.
3. **작업 상태·범위·완료 여부는 Issue가 정한다.** 문서에 "진행 중" 같은 작업 상태를 쓰지 않는다.
4. **복제 금지.** 01·06의 내용을 이 문서나 이슈에 옮겨 적지 않고 링크한다.
5. **가정은 숨기지 않는다.** 가정은 01 §8처럼 목록으로 남기고, 확정되면 출처를 갱신한다.

## 3. GitHub Issue 규칙 (개별 작업의 원본)

- 한 이슈는 한 작업 단위다. 작업 범위·완료 조건은 이슈 본문에 쓴다.
- 도메인 근거가 필요하면 01의 해당 절(예: F5-1, §5)을 링크한다.
- 구조 변경이 필요하면 06의 해당 절을 링크하고, 변경 사유를 이슈에 적는다.
- 완료 판단은 이슈의 완료 조건으로 한다. 검증 규칙은 §4를 따른다(추후 생성).

## 6. 충돌 정책

용어:
- **SSOT 문서:** §1 지정표의 원본 (01, 06, 그리고 개별 작업의 원본인 이슈).
- **참고 문서:** §1 "보조 원본"에 적힌 문서 (03, 04, 05, HANDOVER, README 등).

정책:

1. **참고 문서와 SSOT가 충돌하면 SSOT를 우선한다.** 참고 문서를 고치거나, 참고 문서의 내용을 근거로 SSOT를 바꾸지 않는다.
2. **이슈와 SSOT가 충돌하면 `NEEDS_HUMAN` 상태를 선언하고 사람에게 판단을 요청한다.**
3. **SSOT와 SSOT가 충돌해도 `NEEDS_HUMAN` 상태를 선언하고 사람에게 판단을 요청한다.** (예: 01과 06의 내용이 서로 다름)
4. **AI는 충돌이 발생하면 자신의 판단대로 행동하지 않는다.** 충돌을 해소하는 수정, 우선순위 임의 선택, 가정에 따른 구현을 하지 않는다.

`NEEDS_HUMAN` 선언 시 AI가 할 일:
- 충돌한 위치를 명시한다 (문서 경로와 절, 또는 이슈 번호와 본문 항목).
- 충돌 내용을 양쪽 원문 그대로 인용한다. 요약으로 바꾸지 않는다.
- 해당 작업은 멈추고, 충돌과 무관한 부분만 진행할 수 있다. 충돌 영역에는 손대지 않는다.
- 판단 가능한 선택지가 있으면 나열하되, 추천을 근거로 진행하지 않는다.
